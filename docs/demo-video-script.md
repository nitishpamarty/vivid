# Demo video script — working draft

Headline argument (the line the whole video is built to prove):

> **"Data visualization is visual. It should be visual, and it should be iterative."**

Placement recommendation: say it plain over a static chart at 0:00 as the hook, then land it again at 2:50 as a callback once the three proof points have earned it. Cutting the callback is a legitimate edit if the video feels front-loaded.

## Timeline (3:00 total)

| Time | Beat | Screen | Voiceover / point |
|---|---|---|---|
| 0:00–0:12 | Cold open / hook | Static, generic chart on screen, cursor motionless | "Data visualization is visual. It should be visual, and it should be iterative." Cut. |
| 0:12–0:40 | Argument 1 — Visual co-piloting | Live browser canvas: user asks for a change, agent edits the chart in place, tries a version, both look at it, ask for another pass | Headless MCP tools stop after generating one static chart. WebMCP keeps agent and human co-piloting the *same visible canvas* — see what works, see what doesn't, together. |
| 0:40–1:10 | Argument 2 — Semantic layer autonomy | User asks about a metric; agent pulls definitions/relationships through the page's existing semantic-layer connection, no tab-switching; agent pushes back on the user's framing | Business meaning arrives through the page itself — no hunting for the right dataset or metric. Agent has enough context to disagree and guide, not just execute clicks. |
| 1:10–1:45 | Argument 3 — Live-call speed | Split screen: user on a call talking about something unrelated; agent adjusts colors/filters per a typed request; dashboard updates live | The practical payoff: this works under real conditions, not just in a demo. User keeps talking, agent keeps building. |
| 1:45–2:15 | Future state — WebMCP + MCP combined | Simple node diagram: agent at center, wired simultaneously into the viz canvas (WebMCP) and the semantic layer, dotted line to "other data source" | Viz tools are racing to ship their own MCP — but that locks judgment inside the vendor's agent. WebMCP lets the same agent reach outside the tool, combine what's on screen with outside knowledge. The first-mile automation MCP offers isn't the whole story — the iterative middle is where the real work happens. |
| 2:15–2:50 | Recap montage | Fast cuts back through the three proof beats, no new footage | Rhythm beat before the close — reinforce, don't introduce. |
| 2:50–3:00 | Callback + end card | Agent and user looking at the same finished chart | Restate the headline. CTA. |

## Notes to self

- The three core arguments, in the order that seems to sell best: (1) visual + iterative vs. headless, (2) semantic-layer-driven autonomy, (3) live-call speed. Point 1 is the thesis; 2 and 3 are proof.
- Future-state bit is a bonus argument, not a fourth proof point — keep it visually distinct (diagram, not live demo) so it doesn't compete with the product footage.
- Open question: does the callback at 2:50 feel earned, or redundant with the cold open? Flag on first cut review.
